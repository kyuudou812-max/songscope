# Claude Code（クラウド版）の使い方ガイド

調査日: 2026-10-08
対象: スマホ・ブラウザの Claude アプリの「Code」から使うクラウドセッション
出典: Claude Code 公式ドキュメント（末尾に一覧）

---

## 1. まず知っておくこと：Claude Code の「記憶」の仕組み

| 何が残るか | 何が消えるか |
|---|---|
| 会話の履歴（同じセッションを開き直せば読める） | 作業用の環境（しばらく放置すると回収される） |
| GitHub に push したファイル | 環境の中だけにあるファイル（push していないもの、作業用フォルダ） |
| **CLAUDE.md** に書いたこと（毎回のセッションの最初に読み込まれる） | 長い会話の前半の細かい部分（会話が長くなると自動で要約される） |

- **新しいセッションの Claude は、前のセッションのことを覚えていない。** 残したいことはリポジトリに書いて push する。
- 会話が長くなると、自動で要約（compaction）が入る。要約で細部が落ちることがあるので、決まったことはファイルに残すのが安全。
- このプロジェクトでは、決定事項を `ccfolia-opening/README.md` や `STORYBOARD.md` に書いて push している。

## 2. CLAUDE.md：プロジェクトの「申し送り書」

リポジトリの一番上に `CLAUDE.md` を置くと、**新しいセッションの最初に毎回自動で読み込まれる**。

書くとよいこと：
- このリポジトリで何をしているか（数行）
- 守ってほしい決まりごと（例：シナリオ本文はリポジトリに入れない、作業は日本語でやさしく説明する）
- よく使う手順（例：プレビューの書き出し方）

書かないほうがいいこと：
- 長い説明、すぐ変わる情報、ファイルを読めば分かること
- 長すぎると、大事なルールが埋もれて守られにくくなる。「この行を消したら Claude が間違えるか？」で判断する

注意：CLAUDE.md は、**セッションが開いたブランチ（ふだんは main）にあるもの**が読まれる。作業用ブランチに置いただけでは効かない。

## 3. うまく頼むコツ

### 具体的に伝える
| ぼんやりした頼み方 | 伝わりやすい頼み方 |
|---|---|
| 「もっとかっこよくして」 | 「9秒のタイトルが出るのが早い。0.5秒遅らせて、もっとゆっくりにじむように」 |
| 「なんか違う」 | 「顔はいらない。隙間のざらつきは残す」 |
| 「テストした」 | 「Aの棒は3本そろった。カットインだけ0.3秒遅れた」 |

- **秒数・場所・どう変えたいか**の3つがあると、1回で直せることが多い。
- 動画への指摘は「○秒の、画面の右上の文字」のように、時刻と場所で伝える。

### 見せられるものは見せる
- **画像・スクリーンショット**：そのまま添付すれば Claude は見られる。
- **画面録画（mp4）**：Claude は動画を直接「再生」はできないが、コマを切り出して確認できる。ココフォリアでの見え方の確認に使える。
- **PDF・文書**：添付すれば読める（今回のシナリオのように）。

### 確認の手段を用意する
公式ドキュメントで一番強調されていること：**Claude が自分で結果を確かめられる手段があると、仕上がりが良くなる。**
- このプロジェクトでは、書き出した画面を Claude 自身が画像で確認してから渡している（その過程で不具合を2つ見つけて直した）。
- 「完成したらスクショを撮って、どこが違うか確認してから直して」のように頼むのも有効。

### 大きい仕事は「質問してもらう」から始める
新しいことを始めるときは、こう頼むと抜けが減る：
> 「〇〇を作りたい。始める前に、決めておくべきことを質問して。終わったら仕様を ○○.md にまとめて」

### 途中で方向がずれたらすぐ言う
- 早めに止めて言い直すほうが、あとで大きく直すより速い。
- 同じことを2回以上直しても直らないときは、**新しいセッションで、学んだことを最初に書いて頼み直す**ほうがうまくいく。

## 4. セッションの分け方

- **話題が大きく変わったら、新しいセッションにする。** 1つの会話に関係ない話が混ざるほど、Claude の精度が下がる。
  - 例：「広告の研究」と「ココフォリアのOP制作」は別セッションでよかった
- 新しいセッションに移るときは、
  1. 今の状況をファイルに書いて push する（または CLAUDE.md に申し送りを書く）
  2. 新しいセッションで「`ccfolia-opening/README.md` を読んで続きをやって」と頼む

## 5. 環境の設定（必要になったら）

| やりたいこと | どこで変えるか |
|---|---|
| 調べ物でブロックされたサイトを開けるようにする | セッション上部の環境メニュー → 編集 → ネットワークアクセス → 許可ドメインに追加 |
| 毎回同じソフトやフォントを入れておく | 同じ画面の「セットアップスクリプト」 |
| APIキーなどを使う | 同じ画面の環境変数・シークレット |

このプロジェクトで実際にブロックされたサイト：`docs.ccfolia.com`（ココフォリア公式ドキュメント）、`note.com`、`ccfolia.fanbox.cc`。これらを許可すれば、ココフォリアの最新仕様を Claude が直接確認できるようになる。

## 6. 繰り返す作業は「スキル」にできる

`.claude/skills/<名前>/SKILL.md` に手順を書いておくと、`/名前` で呼び出せる。

- 例：「新しいシナリオのOPを作る」手順をスキルにしておけば、次のシナリオでは `/ccfolia-opening` で同じ流れを始められる。
- CLAUDE.md との違い：CLAUDE.md は毎回全部読み込まれる。スキルは必要なときだけ読み込まれる。長い手順はスキル向き。

## 7. スマホアプリで使うとき

- 作業はクラウドで続くので、アプリを閉じても止まらない。
- 返事を待たずに次のメッセージを送ると、作業の区切りで読まれる（取り消しも可能）。
- 終わったセッションはアーカイブして整理できる。

## 8. Claude にできないこと（このプロジェクトに関係するもの）

- **ココフォリアの操作**：アップロードや設定はユーザーが行う。
- **音を「聴いて」判断すること**：波形や音量の数値は分析できるが、怖さや聞き心地の判断はユーザーに頼る。
- **他社の AI（Gemini など）を呼ぶこと**：この環境からは使えない。作った音声ファイルを渡してもらえば組み込める。
- **前のセッションの記憶**：ファイルに残したものだけが引き継がれる。
